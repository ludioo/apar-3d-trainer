# T4.12: Chip nomor darurat persisten

30 Oktober 2026, Asia/Jakarta. Validasi Q1-Q3, lalu planning, disetujui Barkah sebelum implementasi. **Acceptance final diterima 30 Oktober 2026:** Barkah mengonfirmasi sudah mengecek T4.12 dan lolos, meminta task/tiga checklist selesai, pembaruan dokumen serta commit/push ke develop. Seluruh catatan historis menunggu acceptance T4.12 ditutup. Check/build dijalankan ulang sebelum commit; browser tidak diulang karena penutupan hanya mengubah dokumentasi. Rincian perangkat/browser pengguna tidak diberikan sehingga batas QA AI tetap berlaku. Tidak lanjut task berikutnya atau mengubah main/deploy produksi. Perubahan lokal existing pada AGENTS.md, implementation-plan.md, prompts.md, library-research.md dan bukti task lama dipertahankan di luar commit T4.12.

## Perubahan dan alasan

- Dua tautan telepon langsung, sumber dan catatan cakupan Indonesia tersedia di topbar bersama, bukan subtree fitur. Ruang topbar diukur observer existing; panel/sheet mengikuti batas aktual. Desktop rata kanan, HP nomor di atas sumber/catatan.
- Data nomor/URL tetap dari emergency.json. Empat key emergency.chip.* mengikuti applyDom; heading tersembunyi memberi nama region dan aria-describedby menghubungkan 112 ke catatan. Initializer sekali sebelum viewer sehingga loading/error/fallback juga mempunyai akses.
- Chip memakai surface-solid/text, border text-muted, radius-pill, font token 14px, informasi pendamping 12px, target tautan minimal 44x44px. Bentuk chip menandai dua aksi cepat; catatan dibuat lebih kecil untuk hierarki. Fokus accent untuk keyboard, tanpa ikon/animasi/aset baru. Arah Industrial Safety Studio: ENERGY 1 / RHYTHM 1 / MOTION 1.
- QA close-up tabung desktop menemukan pin tuas y81,45-125,45 tertutup header sampai y118. Batas atas opsional placePin kini dipakai oleh hotspot Configure/kuis dan target PASS; hitbox utuh berpindah ke y122-166 dengan celah 4px. Anchor garis tetap di titik 3D asli. Model, kamera dan oklusi tidak berubah.
- QA visual teks topbar 200% menemukan label tab bertumpuk; overflow-wrap/text-align menjaga label di dalam target. Aturan fallback WebGL disesuaikan untuk menyembunyikan baris tab tanpa kehilangan baris darurat.
- Tidak ada API publik/skema/migrasi/storage/analytics/dependency baru. Teks K3 lengkap di fitur/PDF/About tetap tersedia. GLB identik dengan HEAD, blob 43cf956321ab35d1b12f1affdfdaa2d8fa4153d4, 695.084 byte.

## Pemeriksaan yang dapat diulang

Server: dev 5202, preview produksi 4202, keduanya bind 0.0.0.0. Desktop `http://localhost:4202/#configure`; HP satu jaringan `http://192.168.100.4:4202/#configure`. Keduanya merespons HTTP 200 pada pemeriksaan ini. Jika server berhenti, jalankan di terminal terpisah:

```text
node node_modules/vite/bin/vite.js --host 0.0.0.0 --port 5202 --strictPort
npm run check
npm run build
node node_modules/vite/bin/vite.js preview --host 0.0.0.0 --port 4202 --strictPort
node .cursor/t4.12-check.cjs http://localhost:4202
node .cursor/t4.12-check.cjs http://localhost:5202 --dev
node .cursor/t4.12-squeeze.cjs http://localhost:4202
```

Harness menggunakan Playwright/Chrome yang sudah tersedia, tanpa install. browser-use doctor gagal daemon/koneksi, sehingga memakai fallback ini. Wrapper Squeeze menggunakan harness T4.8 dengan prefix baru, tidak menimpa bukti lama. Chrome headless dan konteks tes terisolasi dari profil pengguna.

- Pada 844x390, topbar sekitar206px dan panel maksimal168px menyisakan kanvas16px. Snap dapat berimpit; pin yang tidak muat disembunyikan. PASS/kuis tetap diselesaikan melalui panel pada run final. Klik tes tidak membuat panggilan darurat. Acceptance umum Barkah diterima, tetapi rincian perangkat atau uji dialer tidak diberikan; tidak mengubah batas QA AI menjadi klaim pengujian fisik.
- Warning Vite chunk >500KB dan warning presisi shader headless existing tetap. Stderr dev juga mencatat ResizeObserver loop completed with undelivered notifications saat QA, seperti catatan baseline T4.8; laporan Playwright errors tetap kosong dan hit-test final lolos. Tidak mengklaim notifikasi itu hilang atau penyebabnya sudah diisolasi. Uji error/fallback sengaja menghasilkan pesan gagal model/WebGL. Tidak mengklaim URL sumber eksternal kembali tersedia saat ini.
